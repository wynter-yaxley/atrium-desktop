# Atrium 设计规范

版本 1.1 · 开发版解析 G3 圆角 · 2026-11-07

这份规范记录 Atrium 已经在用的设计语言，并定出今后新增界面必须遵守的规则。规范里的数值都来自代码：动效曲线来自 [`native/core/motion.h`](../native/core/motion.h)，尺寸来自各面板源文件中的常量。代码与本文不一致时，以代码为准并修正本文。设置中心的“设计规范”页是本文的图解版。

对照标准：Apple《Human Interface Guidelines》（Typography、Layout、Motion、Materials）、WWDC23《Animate with springs》、WWDC18《Designing Fluid Interfaces》、Microsoft Fluent 2、Material Design 3 的 Motion 部分，以及 WCAG 2.2。Atrium 在 Windows 上运行，因此字体、图标和像素换算以 Windows 为准，其余尽量向 macOS 看齐。

---

## 0. 三条原则

1. **让位于内容。** 玻璃只是承载内容的介质，不能喧宾夺主。字色根据玻璃背后的亮度自动切换；装饰（高光、色散、阴影）的强度必须保证文字在任何壁纸上都清晰可读。
2. **运动要像真实物体。** 可打断、位置连续是共同要求；携带速度状态的弹簧改向时保留速度。当前小组件的 Place/Glide 从当前位置重启 240 ms 缓出，尚不保证改向时速度连续；这是实现边界，保留已验收动画。动画按实际时间推进，与帧率无关。
3. **同类事物，同一种处理。** 同一类元素用同一条曲线、同一个圆角、同一档字号。新增界面优先复用本文已有的取值，不为单个界面另造数值。

**单位**：本文所有尺寸以 DIP 为单位（1 DIP = 1/96 英寸，即 100% 缩放下的 1 像素）。绘制时乘以所在显示器的缩放比例（`PopupScale`）。时间以毫秒（ms）或秒（s）为单位。

## 1. 排版

### 1.1 字体

| 用途 | 字体 | 说明 |
| --- | --- | --- |
| 界面文字（中英文） | **MiSans**（小米），三个字重 | 中英文同一套设计，字距与基线天然统一；随软件附带（`Settings\Fonts`），只由 Atrium 私有加载，不安装到系统（D40） |
| 回退 | Segoe UI Variable Text + 系统中文字体 | 字体文件缺失时自动使用；MiSans 没有的字（生僻字、emoji）由系统字体补上 |
| 符号 | Segoe Fluent Icons | 只用字体自带的符号；源码中写作 `L"\uE706"` 这样的转义 |
| 系统状态图形 | 自绘几何（`wifi_glyph`、状态圆环；“系统图标”样式的喇叭与电池） | 没有合适字形时按 iOS 的形状自绘，不用位图 |

MiSans 的字重比名称看起来细一档，Atrium 只带三个文件，按实际粗细使用：

| 文件 | OS/2 字重 | 相当于 | 用途 |
| --- | --- | --- | --- |
| MiSans Medium | 380 | Regular | 正文、行标题、大号展示数字 |
| MiSans Demibold | 450 | Medium | 强调、分组标题、玻璃上的小字、数值 |
| MiSans Semibold | 520 | Semibold | 页标题、标题、时钟、大号百分比 |

原生代码照常请求 Regular / Medium / Semibold，由 `UiTextFormat` 换成上表的实际字重；设置中心的样式直接指定文件，`FontWeight` 保持 Normal，从不合成粗体。

### 1.2 字号阶梯

| 档位 | 字号 / 字重 | 对应 macOS | 用在哪里 |
| --- | --- | --- | --- |
| Large Title | 30 Semibold，行高 38，字距 −1% | Large Title 26 | 设置中心的页标题、“关于”的产品名 |
| Title | 20 Semibold，行高 26 | Title 1（22） | 侧边栏的产品名、空状态标题、日历的月份 |
| Subtitle | 15 Medium，次文字 | Title 3（15） | 页标题下的一句话说明 |
| Row | 15 Medium | Body（13） | 设置中心的行标题；面板正文为 13.5 |
| Value | 15 Demibold，等宽数字 | — | 滑块的数值 |
| Note | 13 Medium，次文字，行高 19 | Callout（12） | 行下方的说明 |
| Section | 13 Demibold，次文字 | — | 分组标题（中文不用全大写） |
| Footnote | 12 Medium，弱文字 | Footnote（10） | 页面底部的补充说明、计数 |
| Caption | 11.5 / 11 | Caption（10） | 时间、百分比、状态（玻璃上自动升为 Demibold） |

设置中心的字号比面板大一档（行标题 15 对 13.5）：它是用户坐下来细看的窗口，面板是一瞥即走的浮层。栏上的时钟随栏的高度缩放：时间取栏高的 0.25 倍、Semibold，日期取 0.19 倍、Medium。

### 1.3 规则

- 一个界面最多使用三档字号。主次关系先用透明度区分（主文字 / 次文字 / 弱文字，见 §5），再用字号，最后才用字重。
- 数字一律等宽（MiSans 的 `tnum`，原生绘制时自动打开）：时钟、音量、电量、计数变化时不会左右跳动。时钟宽度按 `WidestDigits` 预留。
- 中文不使用全大写或字距拉伸。
- 行高取字号的 1.3–1.45 倍。说明文字（多行）用 1.45 倍。
- 截断用省略号，按字符截断，不在单词中间换行。
- 玻璃上的文字靠 halo（一圈 32–35% 不透明度的反色光晕）保证可读；12.5 DIP 及以下的小字再加重一档（Medium → Demibold，`GlassWeight`）。实色背景上不加 halo，也不加重。

## 2. 圆角与曲率

### 2.1 圆角阶梯

| 元素 | 圆角 | 规则 |
| --- | --- | --- |
| 栏 | `cornerRadius`，默认 30（栏高 60 的一半） | 默认保持胶囊比例，端部采用 G3 过渡。允许范围 0–200，实际不超过栏高的一半 |
| 弹出面板（开始、托盘、控制中心、日历、通知） | 与栏相同，限制在 8 到栏高 / 2 之间 | 面板与栏是同一种材质，形状也一致（`ApplySettings`） |
| 面板内的模块（控制中心） | min(面板圆角, 22) | 面板圆角很大时，模块不跟着变成胶囊 |
| 托盘图标底板 | clamp(R − m − 2, 6, 12) | 同心：外层圆角减去边距 |
| 桌面小组件 | 22（格子边长 164） | 约为边长的 13%，与 macOS 小组件的比例一致 |
| 胶囊控件（滑块、按钮、标签） | 高度 / 2 | 两端沿同一连续轮廓收口；圆形旋钮仍用正圆 |
| 悬停与按下的底板 | 8–12 | 不超过所在容器圆角减去边距 |
| 任务栏名称气泡主体 | min(高度 / 2, 16) | 主体与文字保留图标上方原位置，主体间隔 8；底部 5 DIP 小尖角指向图标，靠屏幕边缘时随图标偏移。主体最小高 28，左右内边距 12、上下 6，字号 12.5；尖角与主体使用同一玻璃轮廓，字色仍自适应；尖角是有意的指针，不属于圆角连接 |

### 2.2 同心规则

一个圆角矩形嵌在另一个圆角矩形里时，内层圆角等于外层圆角减去两者之间的边距：

> r_内 = max(r_外 − 边距, r_最小)

内外轮廓的角部中心对齐，沿四边的间距相同；连续轮廓缩小圆角后的曲线不是严格等距偏移。r_最小 取 6。开始菜单的状态胶囊、托盘图标底板和控制中心的模块按这条规则计算。

### 2.3 曲率

- **设计契约：所有 Atrium 绘制的容器 R 角统一为解析 G3。** 覆盖任务栏、面板、通知、小组件、悬停底板、按钮、开关轨道、照片裁剪、设置中心卡片、下拉菜单、颜色浮层、确认对话框、键盘焦点与设计语言示例。大圆角尺寸和胶囊比例保持原有取值；胶囊也不回退为直线拼半圆。正圆没有直边接缝，曲率恒定，本身满足更高阶连续性。R=0 是明确选择的直角，不宣称其为 G3；文字、线性图标笔画和第三方应用图标内部的美术轮廓不属于容器 R 角。Windows 窗口外框、系统文件选择器和系统菜单由平台绘制，不能将它们宣称为 Atrium 的 G3 实现。
- **轮廓定义。** 令 `R=min(设置半径, 短边/2)`，过渡范围 `L=min(1.6R, 短边/2)`。令 `v=1-(1-1/√2)R/L`，`a=max(0.02, (2v⁴-v²)/(1-v²))`。在四分之一角的局部坐标内使用 `F(x,y)=f(x/L)+f(y/L)-1=0`，其中 `f(t)=t⁴/[a+(1-a)t²]`。1.6 的过渡范围参考 Figma iOS 60% 平滑的视觉尺度；空间足够时，中点保持原半径的 45° 内缩量。空间不足时收缩过渡范围，`a` 仍保持正数，不能切回圆弧。完整正圆单独使用 `a=0` 的圆方程。
- **G3 证明。** `f(0)=f′(0)=f″(0)=f‴(0)=0`，`f′(1)=2(1+a)>0`。由隐函数定理，接点处 `y(x)=1-x⁴/[2a(1+a)]+O(x⁶)`，因此 `y′(0)=y″(0)=y‴(0)=0`；曲率 `κ=0` 且弧长方向的曲率变化率 `dκ/ds=0`，与直边两侧一致。这是解析构造的约束，不以“看起来平滑”或位置拟合误差代替。
- **统一实现。** 原生 `corner_profile.h`、着色器 `glass.hlsl` 和设置中心 `CornerProfile.cs` 使用相同参数与隐式方程。几何覆盖率直接从 `F=0` 计算；材质折射需要的近似距离与几何边界分开。删除 16 段三次拟合路径，以及 WinUI 自带圆弧对自绘内容的裁剪。Direct2D 用 A8 角部蒙版，照片、波纹和实色填充走同一入口；长度变化复用九宫格角部，缓存按 Direct2D 资源域区分，最多 64 项且按 4 MiB 预算逐出。设置中心同样缓存角部，限制为 64 项 / 4 MiB；逻辑 `Paint` / `Edge` 与实际绘制笔刷分离，保留 WinUI 视觉状态的恢复行为。按钮沿用原来的颜色资源与 83 ms 过渡，无全局逐帧遍历。
- **原生材质与裁剪。** 照片与 Acrylic 笔刷继续由 XAML 管理，保留实时位图更新、对齐、过渡与系统材质策略。当前可见边界使用解析轮廓采样后的有限折线裁剪，仍属于 A08 缺口；Win2D 只建立设备无关路径，不创建额外的 `CanvasDevice`。有贴边子内容的对话框也裁剪子树，避免子内容盖住圆角。`ContinuousControls.xaml` 以当前 WinUI 2.6.4 的模板为基础，仅接入几何绘制属性，保留布局、命名部件和动效。
- **玻璃融合。** 融合的平滑最小值改为三阶连续的多项式，接点满足 `P(1)=1/2`、`P′(1)=1/2`、`P″(1)=P‴(1)=0`，中点 `P(0)=1/4`。保留原融合宽度与中心鼓起深度。此条件不单独证明任意融合零等值线均正则；实际形状、间距还需检查梯度，拓扑分裂瞬间不作全参数 G3 保证。
- **嵌套与描边。** 外层和内层分别按同一解析方程计算，内层半径取外层减去边距或线宽；不把相似曲线误称为严格法线等距偏移。HRGN 点击区域和合成器路径是该轮廓的离散输出。严格 G3 指解析源边界的性质。解析方程直接生成最终像素覆盖率属于栅格化；把采样点先连成有限折线再做几何裁剪，会引入新的可见边界，不能把该路径称为数学 G3。HRGN 只用于整数输入区域。截图不能代替导数证明。

当前实现范围：原生填充、描边、小组件内容蒙版、独立玻璃以及设置中心实色/渐变使用解析覆盖率。设置中心 ImageBrush、AcrylicBrush 与 ClipChildren 仍走有限折线路径，尚未改为解析覆盖率。4 MiB 只限定角部蒙版缓存，不等于全部合成显存上限。

### 2.4 Apple / Figma 对照与验收

- Apple 的 [App icons](https://developer.apple.com/design/human-interface-guidelines/app-icons) 要求系统遮罩与界面、设备轮廓协调，并以官方图标网格确定比例；[continuous](https://developer.apple.com/documentation/swiftui/roundedcornerstyle/continuous) 描述连续曲率。公开资料没有给出可直接照搬的统一 G3 解析公式，因此本文不将自定义公式冒称为 Apple 的专有实现。
- Figma 的 [圆角与平滑](https://help.figma.com/hc/en-us/articles/360050986854-Adjust-corner-radius-and-smoothing) 将 iOS 预设设为 60%；其 [squircle 技术文章](https://www.figma.com/blog/desperately-seeking-squircles/) 明确说明三次曲线近似的取舍。Atrium 参考轮廓比例与平滑过渡原则，以本节的解析条件额外保证严格 G3，不能用 Figma 的平滑百分比替代导数验收。
- 验收同时检查接点的切线、`κ`、`dκ/ds`；覆盖普通卡片、半高胶囊、小尺寸控件、描边与照片裁剪。核对原生 / CPU 预览 / 合成器蒙版的参数一致性，并检查缓存命中后的绘制耗时及应用内动画。不得通过降低刷新率、改动动画时长或隐藏缺陷来通过验收。
- 本次独立验证：六组不同尺寸 / 半径的 Taylor 系数检查通过，正圆与 R=0 单独核验；七组原生 / C# 参数与各 129 个轮廓采样点一致。176 × 176、R46 卡片的 Direct2D 九宫格输出与解析覆盖率逐像素 alpha 最大差为 0/255。20 个持续改变长度的填充在软件绘制探针中约 0.4 ms / 帧；这个局部耗时不代表整机帧率保证。

## 3. 动效

### 3.1 原则

1. **可打断。** 共同要求是从当前位置改变目标，保持位置连续。`motion::Spring::Step` 同时保存位置和速度；小组件的 Place/Glide 重新开始 EaseOut，暂不宣称速度连续。
2. **与帧率无关。** 弹簧用解析解推进，渐近用指数函数推进；60 Hz、144 Hz 和偶尔掉帧时，同一时刻元素都在同一位置。
3. **交给合成器。** 弹出面板的缩放和淡入由 DirectComposition 播放：弹簧被转换成三次曲线段交给合成器，界面线程卡住时动画仍然流畅。
4. **不用线性曲线。** 可见的位移、缩放和淡变都不用线性曲线。只有本身就随时间匀速变化的量（倒计时、进度）才用线性。
5. **出场比入场快。** 入场是弹簧或缓出，出场是更短的缓出，并且不带回弹。

### 3.2 弹簧

弹簧参数按 Apple 的方式给出：**时长**（response，无阻尼时振荡一个周期所需的秒数）和**回弹**（bounce，等于 1 − 阻尼比）。换算成物理参数（质量为 1）：刚度 k = (2π / 时长)²，阻尼系数 c = 4π(1 − 回弹) / 时长。

| 名称 | 时长 | 回弹 | 阻尼比 | 用途 | 实测表现 |
| --- | --- | --- | --- | --- | --- |
| `kPop` | 0.36 s | 0.38 | 0.62 | 弹出面板出现：缩放 0.92 → 1 | 约 155 ms 第一次到达原大，峰值 1.0067，0.6 s 内完全静止 |
| `kSmooth` | 0.48 s | 0.23 | 0.77 | 状态圆环的填充（电量、音量、亮度） | 超调不到 5%，约 0.4 s 到位 |
| 通知堆叠 | 0.60 s | 0 | 1.0 | 滚轮翻看通知后吸附到某一张 | 不超调；滚动一格至少移动一张 |

`kPop` 的回弹比 SwiftUI 的 `.snappy`（0.15）大，因为它的位移只有 8%：峰值只比终点大 0.67%，人眼感觉到的是“弹出来”的力度，而看不到来回晃动。

### 3.3 缓动曲线

| 名称 | 公式 | 用途 |
| --- | --- | --- |
| 缓出 `EaseOut` | 1 − (1 − t)³ | 淡入淡出、换页、列表依次出现、字色渐变 |
| 回弹缓出 `EaseOutBack(s)` | 1 + (s + 1)(t − 1)³ + s(t − 1)² | 自带轻微超调的出现：开始菜单格子（s = 1.5）、栏从底边升起（s = 1.2） |
| 缓入缓出 | ½ − ½·cos(πt) | 只用于栏自动隐藏时滑出屏幕 |
| 指数渐近 `Approach(rate)` | 每帧乘以 e^(−rate·dt)，时间常数为 1/rate | 跟随指针的状态：悬停（`kHoverIn` 20/s、`kHoverOut` 11/s）、按下（30/s）、栏的位移（14/s，约 0.3 s） |

### 3.4 时长

| 场景 | 时长 | 曲线 |
| --- | --- | --- |
| 悬停底板出现 / 消失 | 到 90% 约 115 ms / 210 ms | Approach 20/s / 11/s |
| 弹出面板淡入 | 160 ms | 缓出（与 `kPop` 缩放同时进行） |
| 弹出面板关闭 | 缩放 130 ms 到 0.95，淡出 120 ms | 缓出 |
| 任务栏名称气泡 | 与弹出面板相同：出现用 `kPop` 缩放与 160 ms 淡入；关闭缩放 130 ms、淡出 120 ms，140 ms 后退役 | 复用 `PopVisual`，没有独立曲线；悬停等待仍为 450 ms，已有窗口预览的应用切换仍为 60 ms |
| 列表依次出现 | 每项 240–260 ms，相邻两项间隔 12–14 ms，最多错开 8–18 项 | 缓出 |
| 台前调度的窗口 | 移位约 420 ms，出现与离开约 300 ms（不透明度 0 → 1，缩放 0.9 → 1）；从屏幕边缘滑出 380 ms，自上而下每张晚 32 ms，同时从 56° 转到 22°；收回 210 ms；指针移上去转到约 7°、放大 6%；窗口画面在原位与侧边之间飞行 460 ms，飞回时在 78% 处恢复窗口，之后画面 150 ms 淡出 | 移位：弹簧，时长 0.42 s、阻尼比 0.86；出现与离开：临界阻尼弹簧，时长 0.30 s；滑出：三次缓出；收回：二次缓入 |
| 控制中心换页 | 320 ms | 缓出 |
| 日历换月 | 260 ms | 缓出 |
| 小组件滑回格子 | 240 ms | 缓出 |
| 通知离开 | 340 ms | 缓出 |
| 点击涟漪 | 520 ms（面板）/ 720 ms（栏） | 缓出，透明度按 (1 − t)² 衰减 |
| 字色切换 | 450 ms | 缓出 |
| 应用启动时图标轻跳 | 一次，480 ms，高 0.32 倍图标 | sin²（起跳与落地速度为零） |
| 状态圆环显示音量或亮度 | 停留 1500 ms，切换速度 12/s | Approach |

界面对操作的直接响应（悬停、按下、展开）应在 100–350 ms 内完成。Apple 的系统动画大多在 0.2–0.5 s 之间，Material 3 给“短”“中”两档定的是 50–200 ms 和 250–400 ms。超过 500 ms 的只能是氛围性的变化（字色渐变），不能挡在用户的下一步操作前面。

小组件拉伸时，保留各尺寸的内容布局，只让实际可见边界与两侧拉伸手柄随当前帧尺寸变化；内容统一裁剪到同一解析 G3 轮廓，避免大尺寸内容溢出，也不将多列内容挤压进过渡尺寸。拉伸继续使用原有 240 ms 缓出。

拖动拉伸期间，内容与玻璃临时预留该组件支持的最大尺寸缓冲，动画帧只改变可见轮廓，不逐帧重建交换链和玻璃纹理；松手且动画结束后释放多余空间。预留缓冲不扩大点击范围。

小组件的原生宿主使用稳定的屏幕坐标；尺寸和位置通过交换链的平移矩阵随像素帧一起呈现，避免逐帧移动 HWND 与玻璃画面异步导致固定侧跳动。宿主不分配整屏纹理，绘图资源仍按组件尺寸分配。窗口区域限制在组件及阴影内；过渡时包含上一帧边界以免裁切在途画面，下一次合成后收紧。上一帧提交前的尺寸请求只保留最新值，输入线程不等待渲染，也不另外限制刷新频率。

小组件背景纹理按桌面像素网格对齐裁切原点及 mip 尺寸（64 px，对应最高第 6 级模糊）。伸缩和释放预留缓冲时，同一桌面位置保持相同的模糊采样相位；实时背景继续更新，不通过冻结背景、淡入淡出两张快照或更换材质参数来掩盖跳变。

### 3.5 帧预算

- 以下是验收目标；现有日志仍有超预算帧，不能据此宣称全部达标。须分别关联输入、内容、玻璃和实际呈现；Present 等待不是 GPU 绘制耗时，静止背景更新次数也不是动画帧率。60 Hz 下每帧 16.7 ms。弹出面板每帧的绘制时间应不超过 4 ms（日志中的 `slowest paint`）。动画期间相邻两帧的最大间隔不超过 20 ms（`longest gap`）。
- 资源复用是目标，不是全局零分配声明：RoundStroke、文字格式、后缓冲视图和角部蒙版已复用；Arc、部分裁剪、数字文字布局仍可能在帧内创建。优化须先记录实际动画的分配栈与创建次数，缓存按实际像素字节设上限。
- 栏、玻璃和弹出面板分别绘制：只有面板变化时，不重绘栏。

### 4.2 栏的尺寸如何随屏幕变化

先把屏幕分辨率换算成逻辑宽度：W = 横向像素 / 缩放比例。例如 3200×2000 在 200% 缩放下 W = 1600。再按 W 选择栏的尺寸：

| 逻辑宽度 W | 典型屏幕 | 栏高 | 图标 | 底边距 | 放大倍数 |
| --- | --- | --- | --- | --- | --- |
| < 1280 | 1366×768 @100%；1920×1080 @150% | 52 | 26 | 8 | 1.5 |
| 1280–1679 | 1920×1080 @125%；2560×1600 @175%；3200×2000 @200% | **60** | **30** | **10** | **1.7**（默认） |
| 1680–2399 | 1920×1080 @100%；2560×1440 @125% | 64 | 32 | 12 | 1.7 |
| ≥ 2400 | 2560×1440 @100%；3840×2160 @150% | 68 | 34 | 14 | 1.6 |

这张表背后的规则：

- **图标是栏高的一半**，四周留出四分之一栏高的空白。图标在 100% 缩放下不小于 24 DIP，否则不易点准。
- **栏高约为逻辑屏幕高度的 6%**，不超过 7%。栏占得越多，留给内容的空间越少。
- **放大后的图标不超过 2 倍栏高**：屏幕越大，放大倍数越小，以免放大的图标遮住正在看的内容。
- 圆角始终取栏高的一半（胶囊）。弹出面板的圆角跟随栏，因此同样遵守这张表。
- 这些都是建议的默认值。用户在设置中心改过的值优先，代码只把数值限制在合法范围内（`Settings::Clamp`）。

## 5. 材质与色彩

### 5.1 玻璃

默认（Liquid 预设）：透明度 0.95，模糊 0.5，折射 30，边缘宽度 24，色散 0.3，高光 0.8，阴影 0.3，色调白色。Frosted 预设：透明度 0.80，模糊 1.0，折射 6，边缘 10，色散 0.04，高光 0.45，色调 #F5F5FA。弹出面板、小组件和栏使用同一套着色器（`glass.hlsl`）和同一组参数，保证整个桌面是同一种玻璃。

玻璃还没有准备好时（刚打开的前 300 ms 之内），面板先画一块按色调计算的实色面板顶替，玻璃就绪后再换成玻璃。

### 5.2 字色（ink）

| 用途 | 浅色字（暗背景） | 深色字（亮背景） |
| --- | --- | --- |
| 主文字 | 白，96% | #111317，92% |
| 次文字 | 白，76% | #111317，66% |
| 弱文字 | 白，56% | #111317，46% |
| 分隔线 | 白，24% | 黑，12% |
| 悬停底板 / 按下底板 | 白，20% / 28% | 黑，10% / 16% |
| 卡片 / 卡片悬停 | 白，8% / 20% | 黑，5% / 10% |
| halo | 黑，32% | 白，35% |

- **自动切换**：用玻璃背后区域的亮度（混入色调后）决定字色。亮度高于 0.50 时换成深色字，低于 0.42 时换回浅色字。两个阈值之间不切换，防止在临界亮度上来回闪烁。切换时用 450 ms 缓出渐变。字色按区域分别决定：时钟和图标可以一个用深色、一个用浅色。
- **单色图标跟随字色**：托盘里只有一种白或黑（不带颜色）的图标字形，和文字用同一套判断：白色字形在亮玻璃上换成深色字的颜色，黑色字形在暗玻璃上换成浅色字的颜色，按区域取值、随字色 450 ms 渐变。带彩色角标的只换中性的部分；自带底板的方形图标（不透明部分超过 75%）和黑边白底的双色图标不换。
- **强调色**：#0A84FF（Apple 深色模式下的系统蓝）。**警示色**：#FF453A（暗背景）/ #E0352B（亮背景），只在电量低且没有充电时使用。
- **对比度**：主文字与次文字对玻璃背后的平均颜色至少达到 4.5:1（WCAG AA）。这靠 halo 和自动切换来保证，不靠调低玻璃的透明度。

## 6. 低配置电脑

规范同样适用于集成显卡、4 GB 内存、60 Hz 屏幕的电脑：

- 弹出面板的内容由 WARP（CPU）绘制，不额外创建一个硬件设备（可节省 70–100 MB 显存和驱动内存）。面板关闭后释放交换链。
- 小组件可以把背景切换为“静态壁纸（省电）”：不再实时捕获桌面，只在壁纸变化时重新合成。
- 栏只在背景确实变化时重绘：GPU 先比较新旧背景，相同就跳过；空闲时每分钟只呈现几十帧。
- 动画与帧率无关，掉帧时元素不会变慢，只是少画中间的几帧。

| 网络小组件 | 参照 macOS 的网络小组件，数据来自 Windows 自己统计的网卡计数器（`GetIfTable2`），不抓包、不装服务：每秒读一次各网卡的收发字节数并做差，取当前真正在传数据的那一块；上一秒没有流量时继续显示同一块，免得在空闲的 WLAN 与以太网之间来回跳。虚拟网卡（Hyper-V 的 vEthernet、VPN 的 TAP、Wi-Fi Direct、WFP 与 QoS 过滤层……全机 49 个接口里有 20 个是这类）不计入，否则同一份流量会被算两遍——判据是 `MIB_IF_ROW2.InterfaceAndOperStatusFlags` 的 `HardwareInterface`（真实硬件端口）与 `FilterInterface`（叠在端口上的过滤层），不是名字：别名是本地化的（“以太网-WFP Native MAC Layer LightWeight Filter-0000”），按名字匹配既漏又误；计数清零（网卡重新接入）按 0 处理，不当成一次巨大的流量。小号：标题 12.5，下行 20 / 上行 14.5，一分钟走势图，底部网卡名；中号：标题右侧是网卡与协商速率（“以太网 · 1.0 Gbps”），下行 32 / 上行 18，走势图更高，底部一行“本次接收 / 发送”。数值为半粗的等宽数字，单位小一号并落在同一条基线上（MiSans 行高 1.326 em、基线 1.044 em，故下移 0.381 × 字号差）。走势线是圆头胶囊连成的折线，最新一秒贴右边，不满一分钟时从右侧生长；两条线各有颜色（下行蓝 #0A84FF，上行橙 #FF9F0A），暮色材质下改用两种不透明度区分。纵轴取窗口内峰值向上取整到 1/2/5 × 10ⁿ，空闲时保留 16 KB/s 的下限，几百字节的噪声不会把图填满。没有连接时显示地球图标与“没有可用的网络”。桌面上有此小组件时才读取，每秒一次；点按打开“网络和 Internet” |

| 滚动条 | 1 DIP 细线（次要文字色，悬停时加深），只在滚动时出现，停止后 0.45 秒淡出；可拖动的区域仍有 10 DIP 宽 |

WinUI 的一个限制：控件模板里被视觉状态改动的元素不能再挂隐式过渡（`OpacityTransition` 等），否则 WinUI 会直接崩溃。需要过渡时，把过渡挂在模板外的元素上，或用 Storyboard。
